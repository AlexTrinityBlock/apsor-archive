# frontend/src/app/companion/ — Agent Guide

The chat companion: a free-standing librarian (no strings or control bar) beside the chat box that mirrors what the agent is doing, and carries a persona and lore. It is a supporting domain (like `viewer/`), not a route. Chat mounts it once; the `companions/` workspace (`/companion`) is its per-account configuration page: choice, enable, size (compact/medium/full, default full), opacity mode (opaque/translucent/auto, default opaque), motion, story, and custom companions.

## Architecture

- **Mount:** `component/ChatCompanion.tsx` is the only chat-page mount. It takes the live stream, the composer draft, and a conversation key — state the page already has — so `chat/` never imports companion internals. `ToolStepCard` additionally renders `CompanionLoreTrace` inside a tool step's details.
- **State machine:** `actions.ts` defines the stable action ids (shared with manifests, uploads, and the agent's `companion_action` tool), priorities, fallbacks, and the tool→pose map. `director.ts` is pure: `desiredPose` picks the highest-priority signal and `advanceDirector` enforces a ≈900 ms minimum dwell (held, failure, and approval skip it). `director-engine.ts` owns clocks and timers and is read through `useSyncExternalStore`; React only feeds observations.
- **Agent gestures:** a `companion_action` tool call (`{action}`) overrides automatic poses for ~3 s. A finished `search_knowledge` step whose data carries `lore` earns a brief soft `reading` pose.
- **Placement:** `layout.ts` is pure geometry. Positions are saved per breakpoint as a dock line (`viewport-left/right`, `panel-left/right`) plus vertical fractions for the top and the feet, so they survive window and figure resizes. Drops project the throw velocity and snap to the nearest dock line; the composer band is never covered. Covering the reading column turns the figure into a peek (slide at window edges, shrink and fade elsewhere) until hovered or focused; an open modal hides it; phones always start peeking.
- **Animation:** one `requestAnimationFrame` loop per stage writes CSS variables directly: spring sway pivoting at the feet from drag velocity, plus breathing. The stage draws no strings or control bar; the box adds only `FIGURE_HEADROOM` above the figure for floating effects. Manifests may carry a legacy `anchor` field, which the parser ignores. Poses crossfade only after every frame of the next clip has decoded (`frame-cache.ts`). Multi-frame clips play at the manifest fps, including `pingpong`. Motion is `full`, `reduced` (still poses, no effects), or `off`, and the OS reduced-motion request caps it at `reduced`.
- **Sizing:** `size.ts` is the single source of truth. Size is one continuous level from 0 (Compact) to 1 (Full); `sizeRange(breakpoint, context)` makes Full "as large as this screen allows, up to the native 384×576" (capped by the height above the composer and a share of the content width), and heights interpolate logarithmically so pinch ratios and wheel notches feel equal at any size. Compact, Medium and Full (plus a dynamic "fits beside chat" level when useful) are magnets with engage/release hysteresis; past the ends the figure rubber-bands (hard stop under reduced motion). The account stores `scale` (null = use the `size` preset): a resize sends both `scale` and its derived `size`, a preset button sends `size` with `scale: null`.
- **Direct resizing:** `gesture.ts` is the pure gesture machine (tap, double-tap, move, corner grip, two-finger pinch, Ctrl/⌘+wheel, Escape cancel) and `hook/useCompanionGestures.ts` wires DOM events into it. The overlay previews a live resize by writing `--companion-k`/`--companion-dx`/`--companion-dy` (no React render per frame) and commits once per gesture; keyboard and slider steps coalesce into one server write. Placement is feet-anchored (`SavedPosition.feet`, with old top-only positions still read) so resizing never moves the feet, and `peekGeometry` shrinks or slides a large figure until it fits the gutter. The grip is a `role="slider"`; a size readout, a one-time coach hint, and a polite announcement accompany changes.
- **Opacity:** opacity modes are CSS classes on the overlay (`opacity-opaque|translucent|auto`); avoidance and `useBusySignal` (typing or scrolling) only set `--companion-fade`, which `auto` honours and hover/focus clears. The figure is fully opaque while it is being resized.
- **Assets:** built-in presets live in `public/companions/<id>/` with `manifest.json` and an `index.json` list. Frame extensions come from the manifest (AVIF or WebP); never hard-code them. `manifest.ts` validates untrusted manifests: plain file names inside the character folder, same-origin `/api/` paths, or `blob:` URLs only.
- **Data layer:** `api.ts` is the single seam to the backend. Presets are a deliberate same-origin static-asset fetch. Custom companions come from the generated client (`listCompanions`, `createCompanion`, `updateCompanion`, `deleteCompanion`, `uploadCompanionFrames`, `deleteCompanionFrame`, `reorderCompanionFrames`); their character ids are `custom-<id>` and frame URLs are the server's versioned `url`. Preferences use `getCompanionPreference` / `updateCompanionPreference` (`selected` is `preset:<id>` or `custom:<id>`), with the per-account local store kept only as a first-paint cache. The story (persona and lore) stays behind `COMPANION_STORY_SUPPORTED` until its endpoints are generated; until then the Story editor keeps in-tab drafts.
- **Story:** the persona and lore are authored content and are shown exactly as written, never translated. Lore is never styled as a citation or archive evidence; in chat it appears only in the tool-step details, labelled as the librarian's own memory, and the answer retells it in the librarian's voice.

## Conventions

- Keep pure logic in plain modules with colocated `bun:test` tests (`*.test.ts`).
- Never read refs or call `Date.now()` during render; timers belong to the engine or to effects.
- Only `ChatCompanion` and `CompanionLoreTrace` may be imported from `chat/`; keep those call sites one line each.
- Every UI string lives in the `companion` i18n namespace (plus `core.nav.companion`); character names are data.
- Colors come from tokens; a character's accent is manifest data exposed as `--companion-accent`.
